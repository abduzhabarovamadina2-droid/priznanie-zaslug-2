# Признание заслуг

Модуль **«Признание заслуг»** для цифрового ядра Национального Банка
Республики Казахстан. Сотрудники направляют друг другу благодарности,
модератор и администратор их согласуют, набранные баллы формируют рейтинг
и галерею победителей.

Модуль приводится к модели боевого MeritRecognition (OutSystems): ключ
работника — табельный номер, пять статусов заявки, роли инициатора,
модератора, администратора и руководителя.

## Структура репозитория

```
├── frontend/          прототип интерфейса и локальный статический сервер
├── backend/           API: Node.js + Express + PostgreSQL
├── deploy/            docker compose: PostgreSQL + API + nginx
├── docs/              архитектура, мета-промт, описание проекта
├── вспомогательные/   история прототипа, скрипты правки, дизайн-система
├── документы/         внутренние документы банка (в Git не публикуются)
└── start-dev.ps1      локальный запуск backend + frontend
```

### frontend/

| Файл | Назначение |
|---|---|
| `Признание заслуг.html` | сам прототип — один самодостаточный файл, React вшит внутрь |
| `index.html` | точка входа для веб-сервера, перенаправляет на прототип |
| `config.js` | адрес backend-API (`window.MR_API_BASE`) |
| `employees.json` | справочник сотрудников и учётные записи |
| `merits.json` | справочник заслуг по номинациям (выгружается из прототипа) |
| `Рейтинг.json` | баллы и количество бейджей за год |
| `фото/`, `фото-200/` | фотографии для аватарок: оригиналы и сжатые 200×200 |
| `static-server.js` | локальный статический сервер на порту 8010 |

### backend/

| Папка | Назначение |
|---|---|
| `src/` | приложение: routes → controllers → services → repositories |
| `uploads/` | вложения заявок (создаётся при первой загрузке, в Git не идёт) |
| `migrations/` | схема БД, накатывается `npm run db:migrate` |
| `seeds/` | наполнение справочников из `frontend/*.json` |
| `scripts/` | служебные скрипты (миграции) |
| `tools/` | разовые утилиты администратора: проверка и сброс паролей |
| `tests/` | автотесты API: `npm test` |

## Как запустить локально

```powershell
powershell -ExecutionPolicy Bypass -File .\start-dev.ps1
```

Скрипт поднимает backend и статический сервер фронтенда в отдельных окнах.
Вручную то же самое:

```powershell
cd backend;  npm install;  npm run dev      # http://localhost:4000/api/health
cd frontend; npm start                      # http://localhost:8010/
```

Перед первым запуском: скопировать `backend/.env.example` в `backend/.env`,
заполнить `DATABASE_URL` и `JWT_SECRET`, затем

```powershell
cd backend
npm run db:migrate
npm run db:seed:all
npm run db:rank          # места в рейтинге
```

## Тесты

```powershell
cd backend
npm test
```

67 проверок по всем маршрутам: вход и права, правила заявки, баллы,
вложения, уведомления, очередь писем, журнал действий. Приложение
поднимается прямо в тесте на свободном порту — заранее запускать сервер не
нужно. База берётся из `.env`; всё созданное тестами удаляется в конце
прогона, балансы баллов возвращаются на место.

Адрес API правится одной строкой в `frontend/config.js`.

Прототип открывается и двойным кликом по `frontend/Признание заслуг.html`,
но тогда он работает на встроенных демонстрационных данных: браузер
запрещает читать соседние файлы с диска. Признак того, что данные
подхватились, — строка в консоли браузера (F12):

```
employees.json: 24 people, 4 users; Рейтинг.json: 22 записей
```

Если вместо неё написано `встроенные данные` — сервер не запущен либо файл
не найден, приложение поднялось на резервных данных и показывает плашку
демонстрационного режима.

## Как развернуть стенд

См. [deploy/README.md](deploy/README.md) — `docker compose up -d --build`
поднимает PostgreSQL, API и nginx, наружу торчит только nginx.

## Технологии

- **React 19** — вшит в HTML вместе с приложением, сборка не требуется
- **Node.js 18+, Express 4, PostgreSQL** — backend, JWT-авторизация
- **Docker Compose, nginx** — стенд
- **localStorage** — только токен входа и настройки. Заявки с этапа 3 живут
  на сервере; локально остаются лишь записи, созданные до этого этапа

## Учётные записи прототипа

Демонстрационные, пароль у всех `12345`, подставляется автоматически:

| Логин | Роль |
|---|---|
| `CORP.NB.RK\1` | инициатор |
| `CORP.NB.RK\2` | администратор |
| `CORP.NB.RK\3` | модератор |
| `CORP.NB.RK\4` | руководитель |

Перед выкладкой в контур банка учётки удаляются или пароли меняются.

## Как править данные

Правится только `вспомогательные/исходные-данные/Сотрудники.xlsx` —
`frontend/employees.json` собирается из него. Ручные правки в JSON затрутся
при следующей перегенерации.

## Статус

Этап 6 в работе: сделана часть, не зависящая от инфраструктуры банка. Заявки создаются, согласуются, отзываются и удаляются на
сервере; реестр общий для всех. Баллы списываются при подаче и возвращаются
при отзыве, отклонении и удалении. Повторная заявка на того же сотрудника по
той же номинации отклоняется. Справочники номинаций и заслуг отдаются через
API, места в рейтинге пересчитываются.

Вложения загружаются и скачиваются, уведомления приходят в интерфейс.
Добавлены журнал действий, ограничение попыток входа, автоматический разбор
очереди писем и автотесты.

Ждёт решений банка: адрес AD-сервера для входа по корпоративной учётной
записи, почтовый сервер и адреса сотрудников для писем, сервер под свою
PostgreSQL вместо облачной, сертификат для HTTPS, порядок резервного
копирования. Демонстрационные учётки с паролем `12345` удаляются в момент
выкладки.
