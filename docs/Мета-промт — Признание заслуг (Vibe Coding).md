# 2. ТЕХНОЛОГИЧЕСКИЙ СТЕК

- **React 18+ + TypeScript** (строгий режим), сборка **Vite**.
- **Стилизация:** обычный CSS с CSS-переменными (один `theme.css` + модульные файлы).
  Tailwind допустим, но токены должны остаться CSS-переменными — тёмная/светлая тема
  переключается классом `dark` на `<html>`.
- **Состояние:** React Context + `useReducer` (один `AppStore`). Никаких Redux/MobX.
- **Персистентность:** `localStorage`, ключ `mr_state_v1`. Бэкенда нет — это высокоточный
  интерактивный прототип.
- **Роутинг:** внутренний (состояние `activeSection`), без react-router. URL не меняется.
- **Иконки:** собственные inline-SVG (24×24, `fill="none"`, `stroke="currentColor"`,
  `stroke-width="1.8"`, `stroke-linecap="round"`, `stroke-linejoin="round"`). Никаких icon-библиотек.
- **Экспорт .xlsx:** собственный генератор OOXML без библиотек (см. §5.12).
- **Шрифт:** `Inter, -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, Arial, sans-serif`;
  моно — `ui-monospace, SFMono-Regular, 'SF Mono', Menlo, Consolas, monospace`.
- **Зависимости:** только `react`, `react-dom`. Больше ничего.

## 3.3. Анимации и микровзаимодействия

- Появление карточек — каскад `translateY(16px) scale(.94) → none`, `.5s cubic-bezier(.22,1,.36,1)`,
  задержка `index * 60…80ms`.
- Шкалы/бары растут через `transform: scaleX()` (не через `width` — иначе в связке с
  `backdrop-filter` возможны артефакты отрисовки).
- Бегущий блик по шапкам и активным пунктам меню: `background-size:220% 100%` + `navSheen 6s`.
- Кнопка «Мои награды»: золотой градиент, пульсирующее свечение + расходящееся кольцо.
  Если наград нет — приглушённая, `disabled`, `cursor:not-allowed`, без анимации.
- Аватары призёров: вращающееся кольцо `conic-gradient` (`haloSpin 6s linear infinite`);
  у первого места — корона, покачивается `crownFloat 2.6s`.
- Погода: солнце с вращающимися лучами (`conic-gradient` + mask), дрейфующие размытые пятна.
- Hover на строках/карточках: подъём на 3–5 px + цветная тень.
- Тосты: снизу по центру, живут 2.6 с.
- **Все анимации отключаются** при `@media (prefers-reduced-motion: reduce)`.
- **Никаких счётчиков на `requestAnimationFrame`** для KPI — значения выводятся сразу
  (rAF замерзает в фоновой вкладке и оставляет нули).

# 4. АРХИТЕКТУРА И СОСТОЯНИЕ

## 4.1. Форма глобального состояния

```ts
type SectionKey =
  | 'home' | 'about' | 'zaslugi' | 'faq' | 'rating' | 'refs' | 'admin' | 'lk';

interface AppState {
  user: User | null;              // null → показываем экран входа
  theme: 'dark' | 'light';
  collapsed: boolean;             // сайдбар свёрнут
  activeSection: SectionKey;      // стартовый 'home'
  points: number;                 // доступные баллы текущего пользователя
  records: NewRecord[];           // заявки, созданные в интерфейсе
  overrides: Record<string, Override>;  // изменения по заявкам (ключ — id заявки)
  deleted: string[];              // id удалённых администратором заявок
  store: Dictionaries;            // 4 справочника
  read: Record<string, Record<string, true>>; // прочитанные уведомления: login → id → true
  pts: Record<string, number>;    // остаток баллов по логинам
  toast: string | null;
  awardOpen: boolean;             // открыта карточка награды
  refsVersion: number;            // инкремент при правке справочника
}
```

## 4.2. Персистентность

При каждом изменении `records | overrides | deleted | store | read | pts | user | activeSection`
состояние сериализуется в `localStorage['mr_state_v1']`. При старте — восстанавливается,
включая сессию (пользователь остаётся залогинен после перезагрузки).
Кнопка «Сбросить демонстрационные данные» на экране входа очищает ключ и перезагружает страницу.

> **Важно:** данные обязаны переживать перезагрузку. Выход из системы сбрасывает **только**
> `user` и `activeSection` — заявки, справочники и рейтинг остаются общими для всех ролей.

## 4.3. Поток данных (единственный источник истины)

```
records + overrides + deleted
        │
        ├─► buildRequests()  ─► реестр заявок (Заслуги, Администрирование)
        │
        └─► buildBoard(period) ─► рейтинг ─┬─► KPI-плитки
                                           ├─► «Лидеры признания» (топ-3)
                                           ├─► таблица рейтинга
                                           ├─► «Галерея победителей» на главной
                                           └─► распределение по номинациям

history заявок ─► deriveNotifications(user) ─► колокольчик
store.nominations[].points ─► стоимость благодарности И вклад в рейтинг
```

**Правило:** рейтинг и галерея победителей вычисляются **одной и той же функцией**.
Дублирование расчёта запрещено — числа обязаны совпадать везде.

## 5.3. Раздел «Главная»

Две колонки: контент + «липкая» правая колонка 330 px.

**Левая колонка:**

## 5.4. Карточка призёра (`WinnerCard`) — общий компонент

Используется и в «Галерее победителей», и в «Лидерах признания».

```
┌─────────────────────────┐
│  ЛЕНТА: «1 МЕСТО»       │  золото / серебро / бронза / нейтральная (4-5 место)
│  (свечение в цвете)     │
│      👑 корона (1 место)│
│      ◯ аватар + кольцо  │  вращающийся conic-gradient у топ-3
│         ① медаль        │
│   Ф.И.О.                │
│   Должность             │
│   Подразделение         │
│   ▬▬▬▬▬▬░░░ шкала       │  доля от лидера группы, минимум 8%
│   40 РЕЙТИНГ   🏅 1     │
```

Цвета мест: золото `#fbe9a4 → #e0a91d`, серебро `#f2f5f7 → #b7bfc4`, бронза `#f5d9bd → #c88742`.
У первого места — бегущий блик по карточке. Hover: подъём 5 px, аватар ×1.05, тень в цвете места.
Сетка: `repeat(auto-fill, minmax(158px, 1fr))`, gap 14 px.

## 5.5. Раздел «О программе»

Фото-баннер с наложенным текстом «Платформа Признание заслуг «От благодарности к результату»»
и тремя тезисами. Ниже — «Бейджи программы»: 6 флип-карточек.

- **Лицо:** восьмигранный бейдж (SVG): полигон из 8 точек радиусом 88 (угол `π/4·i − π/8`),
  внутренние окружности r=70/52/46, слово по дуге (`textPath`, дуга `M44,100 A56,56 0 0 1 156,100`),
  эмблема НБРК по центру, блики; ниже название бейджа и номинация; ссылка «↻ Показать награду».
- **Оборот:** награда-статуэтка (SVG 200×300): стеклянная стела, **сверху — название награды**
  (KEREMET / TAMASHA / …), **в центре — тот же бейдж**, снизу — номинация; **подставка окрашена
  в цвет бейджа** (нижняя плита — тёмный оттенок, ступень — основной, блик — светлый).
- Hover по карточке — всплывающая справка: название, слово, номинация, чип «N мотивационных
  баллов», за что присваивается, кого награждают.
- Подпись уровня (GOLD/SILVER/…) в углу карточки **не выводится**.

## 5.6. Раздел «Заслуги» — рабочая область

Над содержимым: «Доступные баллы на текущий месяц: {points}» и кнопка «Экспорт .xlsx».

**Пять вкладок-папок** (визуально — папки с «язычком», счётчиком и подписью):

| Вкладка | Содержимое | Статусы |
|---|---|---|
| Признание заслуг | список работников + поиск | — |
| Проект | заявки в 24-часовом окне | `pending` |
| Черновик | отозванные и возвращённые | `withdrawn`, `revision`, `draft` |
| Отменено | необратимо отменённые | `cancelled` |
| Отправлено | переданные получателю | `sent` |

**Вкладка «Признание заслуг»:** поле поиска сотрудников с выпадающими подсказками
(фильтр по Ф.И.О. и подразделению, закрытие по клику вне) и таблица
`№ | Фамилия | Имя | Отчество | Подразделение | [кнопка «Для направления благодарности»]`
с сортировкой по клику на заголовки.

**Остальные вкладки:** таблица `№ | Заявка | Дата | Работник | Номинация | Инициатор | Статус | →`,
клик по строке открывает карточку заявки.

## 5.7. Модалка «Направить благодарность»

Поля по порядку:

1. Блок получателя: аватар-инициалы, Ф.И.О., подразделение.
2. **Номинация и бейдж признания \*** — `select` из активных номинаций,
   текст опции: `«{номинация} — {название бейджа} · {слово} ({баллы} б.)»`.
3. **Заслуга \*** — `select`, отфильтрованный по выбранной номинации; до выбора номинации
   `disabled` с текстом «Сначала выберите номинацию».
4. **За какое конкретное достижение направляется бейдж \*** — `textarea`, максимум 250 символов,
   счётчик `N/250`.
5. **Готовые фразы** — чипы из активных фраз, клик добавляет фразу в конец текста.
6. Блок стоимости: «Стоимость направления — {баллы} баллов. Останется: {points − баллы}».
7. Подвал: «Отмена» и «♡ Направить благодарность».

`onSubmit` — валидация: не выбрана номинация → «Выберите номинацию»; не выбрана заслуга →
«Выберите заслугу из справочника»; пустой текст → «Укажите, за какое конкретное достижение
направляется бейдж»; `points < стоимость` → «Недостаточно баллов: требуется N».

При успехе: модалка закрывается, списываются баллы номинации, создаётся заявка со статусом
`pending`, показывается тост:

> «Заявка сформирована. Получатель получит Вашу благодарность по истечении 24 часов. В течение
> этого времени у Вас есть возможность отозвать заявку для корректировки.»

## 5.8. Карточка заявки (`RequestCard`)

Секции: **Данные о работнике** (Сотрудник, Должность, Структурное подразделение, Филиал/ЦА,
Заместитель Председателя, Инициатор) · **Данные о заслуге** (Текст заслуги, Дата, Заслуга,
Номинация, Бейдж) · **Подтверждающий документ** (вложение или «Документ не приложен»;
для инициатора — «Прикрепить вложение» / «Удалить вложение») · **История заявки**
(Пользователь / Время / Описание / Комментарий) · **Комментарий** (до 500 символов).

Сверху при `revision` — янтарная плашка «Примечание модератора ДРЧК: {текст}»;
при `pending` — синяя плашка про 24 часа.

Кнопки по роли и статусу:

| Роль | Статус | Кнопки |
|---|---|---|
| Инициатор | pending | Отозвать заявку · Закрыть |
| Инициатор | withdrawn / revision | Отправить (на согласование) · Отменить заявку · Закрыть |
| Инициатор | sent / cancelled | все действия `disabled` · Закрыть |
| Модератор | pending / revision | Согласовать · На доработку · Отклонить · Закрыть |
| Администратор | любой активный | Сохранить · Согласовать · На доработку · Отклонить · Удалить · Закрыть |

«На доработку» требует непустой комментарий, иначе тост «Укажите примечание для возврата на
доработку.». Любое действие дописывает запись в историю: `{ user: текущий, time: сейчас, action, comment }`.

## 5.9. Раздел «Вопрос-Ответ»

Таблица `Вопрос | Ответ` из **активных** записей справочника «Вопрос-Ответ», поиск по тексту,
сортировка по вопросу, счётчик «N из M». Деактивированная запись исчезает из раздела.

## 5.10. Раздел «Администрирование»

Шапка: заголовок «Все заявки модуля «Признание заслуг»», подпись «Показано N из M · {роль}»,
поиск, «Экспорт .xlsx».

Фильтры: **Номинация**, **Статус**, **Инициатор** (выпадающие списки) + «Сбросить».

Таблица: `№ | Инициатор | Сотрудник | Текст заслуги | Дата события | Номинация | Статус | Действия`.
Клик по Ф.И.О. сотрудника открывает **редактируемую карточку** (текст заслуги, заслуга, номинация —
редактируются; дата, сотрудник, инициатор — только чтение). В колонке действий: «открыть» и
«удалить» (корзина, только у администратора).

## 5.11. Раздел «Рейтинг»

1. **KPI-плитки:** Направлено бейджей · Участников рейтинга (только с баллами > 0) ·
   Средний балл (по участникам с баллами) · Отчётный период.
2. **«Лидеры признания»** — блок в дизайне «Галереи победителей»: градиентная шапка с иконкой,
   переключатель «Квартал / Год» внутри шапки (полупрозрачные белые вкладки), подзаголовок
   «Тройка работников с наибольшим рейтингом · {период}» + чип «N лидера», сетка из карточек
   призёров (§5.4). Клик → модалка «Просмотр благодарностей».
3. **«Распределение бейджей по номинациям»** — горизонтальные полосы: диск бейджа, название,
   шкала, значение и доля в процентах; при наведении — подсказка
   «N бейджей · X% от всех направленных · Y баллов за бейдж».
4. **Отчёт «Рейтинг работников НБРК»** — таблица
   `Место | Ф.И.О. | Должность | Филиал/ЦА | Структурное подразделение | Благодарностей | Рейтинг | 6 колонок по бейджам`.
   Место присваивается **только при рейтинге > 0**; остальные строки — прочерк и приглушённые.
   Строка «моя» подсвечивается. Экспорт .xlsx.
5. **Модалка «Просмотр благодарностей»** (широкая, 1120 px): зелёная секция «Благодарности»
   (`№ | Текст заслуги | Дата заслуги | Заслуга | Номинация | Балл | Бейдж | Инициатор`),
   янтарная секция «Взыскания» (`№ | Дата начала | Дата завершения | Вид взыскания | Комментарий`),
   подвал: аватар + Ф.И.О., при наличии штрафа «Начислено N · удержано за взыскания −M»,
   «РЕЙТИНГ {значение}», кнопка «Закрыть».

**Формула рейтинга:**
`rating = Σ (баллы номинации по согласованным благодарностям за период) − Σ (штрафы за взыскания)`, не ниже 0.
Период `quarter` = месяцы 07–09, `year` = все 11 месяцев.

## 5.12. Раздел «Справочники» → «Заслуги»

Хаб из 4 плиток (фирменный градиент, иконка, название, «N записей»):

| Плитка | Иконка | Колонки таблицы |
|---|---|---|
| Номинации | медаль со звездой и лентой | № · Название бейджа · Номинация KZ · Номинация RU · Балл · Активность · Дата/Время · Пользователь · Бейдж · Действия |
| Заслуга | звезда | № · Номинация · Заслуга KZ · Заслуга RU · Активность · Дата/Время · Пользователь · Действия |
| Фраза | речевой пузырь | № · Фраза KZ · Фраза RU · Активность · Дата/Время · Пользователь · Действия |
| Частые вопросы-ответы | знак вопроса в круге | № · Вопрос KZ · Вопрос RU · Ответ KZ · Ответ RU · Активность · Дата/Время · Пользователь · Действия |

В каждом справочнике: кнопка «← Справочники модуля «Признание заслуг»», заголовок
«Справочник «{название}»», поиск, «Экспорт .xlsx», «ДОБАВИТЬ», в строках — «Редактировать» и
«Удалить», внизу «Показано 1 – N из M записей».

**Модальные формы** (кнопки подвала — «ЗАКРЫТЬ» и «СОХРАНИТЬ»):

- **Номинация:** Код · Название бейджа · Название KZ · Название RU · Балл ·
  Активность (чекбокс) · Изображение бейджа (файл).
- **Заслуга:** Номинация (список) · Название KZ · Название RU · Активность.
- **Фраза:** Название KZ · Название RU · Активность.
- **Вопрос-Ответ:** Вопрос KZ · Вопрос RU · Ответ KZ · Ответ RU · Активность.

Сохранение проставляет `dt = сейчас` и `user = текущий пользователь`, инкрементит `refsVersion`
и пишет состояние в localStorage. Изменение балла номинации **немедленно** отражается на
стоимости благодарности и на рейтинге.

## 5.13. Уведомления (выводятся из истории заявок)

`deriveNotifications(user)` проходит по всем заявкам и их истории:

| Событие в истории | Кому | Заголовок |
|---|---|---|
| «Создано» / «Отправлено» | модератору и админу (кроме инициатора) | Заявка поступила на согласование |
| «Направлено на доработку» | инициатору | Заявка возвращена на доработку (+ примечание) |
| «Согласовано» | инициатору | Заявка согласована |
| «Согласовано» | получателю | Вам направлена благодарность (тип `award`) |
| «Отклонено» | инициатору | Заявка отклонена |
| «Изменено администратором» | инициатору | Заявка изменена администратором |
| «Отозвано» / «Отменено» | модератору | Заявка отозвана / отменена инициатором |
| «Приложено вложение» | модератору | К заявке приложен документ |

`id` уведомления = `{requestId}#{historyIndex}`. Сортировка по времени убыванию.
Свои действия себе не приходят. Прочитанное хранится по логину.

Панель: счётчик непрочитанных на колокольчике, «Прочитать все», клик по уведомлению помечает
прочитанным и переводит в раздел (`admin` / `zaslugi` / `rating`); уведомление типа `award`
открывает карточку награды. Внизу сноска: «Уведомления также направляются в личный кабинет,
на электронную почту и в виде push-сообщений.»

## 5.14. Карточка полученной награды

Открывается по золотой кнопке в TopBar или по уведомлению типа `award`. Полноэкранный
праздничный оверлей: канвас-конфетти, кнопка звука, кольца и лучи, крупный бейдж, надписи
«ВАМ НАПРАВИЛИ БЛАГОДАРНОСТЬ» → «Поздравляем!» → название и слово бейджа → номинация →
карточка отправителя (аватар, Ф.И.О., подразделение) → «ЗА КАКОЕ ДОСТИЖЕНИЕ» + текст заслуги →
кнопки «Спасибо!» и «Позже».

**Данные берутся из последней согласованной (`sent`) заявки, где текущий пользователь —
получатель.** Наград нет → кнопка неактивна.

## 5.15. Экспорт .xlsx (без библиотек)

Реализовать генератор OOXML:

1. `crc32(bytes)` — таблица на 256 значений, полином `0xEDB88320`.
2. `zip(files)` — ZIP без сжатия (метод 0): локальные заголовки `PK\x03\x04`, центральный
   каталог `PK\x01\x02`, `PK\x05\x06`. **Пути только через прямой слэш**, `[Content_Types].xml` — первым.
3. Части: `[Content_Types].xml`, `_rels/.rels`, `xl/workbook.xml`,
   `xl/_rels/workbook.xml.rels`, `xl/worksheets/sheet1.xml`.
4. Ячейки: числа → `<v>`, строки → `t="inlineStr"` + `<is><t xml:space="preserve">`, XML-экранирование.
5. Скачивание через `Blob` + `URL.createObjectURL` + `<a download>`.

Кнопки экспорта: реестр заявок, каждый справочник, отчёт «Рейтинг», раздел «Вопрос-Ответ».

## 5.16. Личный кабинет (`lk`)

Карточка профиля (аватар, Ф.И.О., должность, подразделение, руководитель, контакты),
KPI-донат (Выполнено в срок 64% / В работе 26% / Просрочено 10%), мини-рейтинг топ-5 с
подсветкой своей строки, горизонтальные вкладки: Общая информация · Должностная инструкция ·
Имущество · Орг. структура · Мои сотрудники · Заслуги · КПЭ · Опросник · ЭЦП · Анкета сотрудника.

# 6. ДЕМО-ДАННЫЕ (ТОЧНЫЕ СТРУКТУРЫ И ЗНАЧЕНИЯ)

## 6.1. Интерфейсы

```ts
type Role = 'initiator' | 'moderator' | 'admin';
type Status = 'pending' | 'revision' | 'withdrawn' | 'cancelled' | 'sent' | 'draft';

interface User {
  login: string; pass: string; role: Role;
  fio: string; short: string; post: string; dept: string;
  group: string;      // '' или 'AdminMeritRecognition'
  points: number;     // лимит баллов на месяц
}

interface BadgeArt {
  tier: 'GOLD'|'SILVER'|'BRONZE'|'GREEN'|'BLUE'|'YELLOW';
  name: string; word: string; desc: string;
  ring: string; shine: string; dark: string; ped: 'dark'|'light';
}

interface Nomination {
  id: string; code: string; badgeName: string;
  nameKz: string; nomination: string;   // RU
  points: number; active: boolean;
  dt: string; user: string;
  badge: string;  // «{name} · {word}»
  word: string; art: BadgeArt;
}
interface Merit  { id: string; nomination: string; meritKz: string; merit: string; active: boolean; dt: string; user: string }
interface Phrase { id: string; phraseKz: string; phrase: string; active: boolean; dt: string; user: string }
interface QA     { id: string; qKz: string; q: string; aKz: string; a: string; active: boolean; dt: string; user: string }
interface Dictionaries { nominations: Nomination[]; merits: Merit[]; phrases: Phrase[]; qa: QA[] }

interface HistoryItem { user: string; time: string; action: string; comment: string }

interface NewRecord {   // создаётся модалкой
  date: string; emp: string; dept: string; badge: string;
  nomination: string; merit: string; comment: string;
  cost: number; status: Status;
}
interface Override {
  status: Status; note: string; doc: string | null;
  fields?: Partial<Pick<Request,'meritText'|'nomination'|'merit'>>;
  history: HistoryItem[];
}
interface Request {
  id: string; status: Status;
  emp: string; post: string; dept: string; branch: string; vice: string;
  initiator: string; date: string;
  meritText: string; merit: string; nomination: string; badge: string;
  doc: string | null; note?: string;
  history: HistoryItem[];
}

interface Employee { f: string; n: string; o: string; d: string }
interface Person {   // участник рейтинга
  fio: string; post: string; branch: string; dep: string; dept: string;
  n: number; me?: boolean;
}
interface Penalty { from: string; to: string; kind: string; note: string; cost: number }
interface Grant {
  no: number; text: string; date: string; month: number;
  merit: string; nomination: string; points: number;
  art: BadgeArt | null; badge: string; initiator: string;
}
```

# 8. ЧЕГО НЕ ДЕЛАТЬ

- Не добавлять поля формы КПЭ (Цель, Показатель, Единица измерения, Вес, Источник данных,
  Порог, Вызов) — это другой модуль.
- Не создавать раздел «Отчётность МФЦА».
- Не анимировать `width` у шкал внутри карточек с `backdrop-filter` — использовать `transform`.
- Не использовать имя CSS-класса `act` для модификаторов — оно занято кнопкой-иконкой 28×28.
- Не сбрасывать заявки при выходе из системы.
- Не дублировать расчёт рейтинга — только одна функция на всё приложение.
- Не подключать сторонние библиотеки иконок, таблиц, графиков и xlsx.
